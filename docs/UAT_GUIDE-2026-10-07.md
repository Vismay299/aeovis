## Deploy the content rescue schedule

Run these commands on the same K3s server as the existing scan rescue after the code is deployed and historical-job recovery is approved:

```sh
sudo k3s kubectl get secret perceev-cron
sudo k3s kubectl apply -f worker/k8s/content-cron.yaml
sudo k3s kubectl get cronjob perceev-content-cron
sudo k3s kubectl create job --from=cronjob/perceev-content-cron perceev-content-rescue-check
sudo k3s kubectl logs job/perceev-content-rescue-check
```

Run from a checkout containing the manifest, or upload that file and use its actual path. The Secret must contain the same `CRON_SECRET` as the live Vercel deployment; never paste its value into chat. A 200 response proves the sweep reached the route; check job heartbeat/stage and final item separately to prove recovery. A 401/403 means authentication failed; a 3xx means deployment protection or the target origin needs correction. The route can resume paid model calls, so only run the manual check after selecting wanted work.
