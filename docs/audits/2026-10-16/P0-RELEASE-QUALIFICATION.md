The v2 verifier treated plain text whose first line had been redacted (it begins with `[REDACTED]`) as malformed JSON, so storage would have refused a correctly redacted text capture; it now distinguishes that prefix from JSON. A pre-merge code review of PR #14 led to five more corrections. (1) The text cookie pattern no longer redacts to end of line: it removes each `;`-separated cookie pair. Before, a whitespace-collapsed source page containing `Cookie:` lost all text after that point. (2) Scan-level share of voice and citation share come from the primary engine slice's DTO only for single-engine scans. That slice is not a blended figure, so multi-engine reports keep their stored scan-level values. (3) The v1 corruption heuristics (malformed bracketed text, cookie pairs after `;`) apply only to v1 captures. Before, v2 answer text such as `[1] Password: …` or `token=x;y=1` caused a correctly redacted capture to be refused. (4) A withheld latest or previous trend reading now states its own qualification reason instead of a misleading context change. (5) Trend points omit the eligible-prompt ID list, which comparison does not use. Deferred with reasons: the sensitive-key list stays broad and privacy-first, so fields such as `prompt_tokens` or `author` inside JSON payload strings are redacted, as object payloads already were.
