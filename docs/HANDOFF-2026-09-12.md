## How the orchestration works (unchanged)

One controller dispatches implementer/test-author/verifier/surveyor/scribe
sub-agents. `orchestrate.mjs` is the only writer of `tasks.json` and enforces:

1. A task cannot close without a passing verification from an agent that did
   not write the code.
2. A close must carry a `file:line` citation that resolves.

```
status | next | show | claim | submit | verify | block | unblock
add | rule | amend | depend | render | validate
```

Run `validate` before every commit. `render` regenerates the human tracker
from the ledger, so it cannot drift.

**Proven-out method from this session, worth keeping**: dispatch verifiers
concurrently into isolated git worktrees rather than serially. The old
one-at-a-time rule existed because verifiers sabotage source to prove a test
catches the regression, and concurrent verifiers sharing one tree see each
other's sabotage. Isolated worktrees remove the shared state entirely, so
running them concurrently is safer, not just faster — proven across roughly 40
verifications this session with mutually consistent verdicts.
