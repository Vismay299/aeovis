## How the orchestration works

One controller dispatches five worker roles. `orchestrate.mjs` is the only
writer of `tasks.json` and enforces the two rules the whole thing exists for:

1. **A task cannot close without a passing verification from an agent that did
   not write the code.**
2. **A close must carry a `file:line` citation that resolves to a real file.**

```
status | next | show | claim | submit | verify | block | unblock
add | rule | amend | depend | render | validate
```

`accept` is deliberately immutable — `amend` refuses to touch it. Moving an
acceptance criterion to fit what got built is the exact failure this prevents.
`depend` *can* change edges, because a dependency is a claim about the world
and can simply be wrong, but it requires a recorded reason.

Run `validate` before every commit. `render` regenerates the human tracker, so
it cannot drift from the ledger.

### Lessons already paid for

- **Verifiers must run one at a time.** They break source deliberately to
  prove a test bites; concurrent verifiers see each other's sabotage.
- **Two implementers must never share a file.** Check `anchors` before batching.
- **Tell every worker that other tasks' changes are in the same tree**, and to
  judge only the files its own evidence cites.
- **Dispatch in the background.** A foreground shell caps at ten minutes and
  will kill a worker mid-task.
